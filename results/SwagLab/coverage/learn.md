# Comparison Report Structure Template

This document outlines the standard structure to be used for reporting comparative analysis, such as benchmark results, coverage comparisons, or model evaluations.

## 1. Primary Comparison Section
**Heading:** `## [Topic] Comparison ([Directionality, e.g., Higher is Better])`

This section contains a ranked data table comparing the primary entities across key metrics.

**Table Columns:**
*   `Rank` (Using medal emojis for top 3: 🥇 1, 🥈 2, 🥉 3, then integers)
*   `[Entity Name]` (e.g., Model, System, Tool)
*   `[Category/Strategy]` (e.g., Strategy, Approach, Prompting Method)
*   `[Primary Metric]` (e.g., Coverage, Accuracy, Speed) - *Often bolded*
*   `[Secondary Metric]` (e.g., Missed Cases, Error Rate, Cost)

## 2. Key Findings Section
**Heading:** `## Key Findings`

This section distills the raw data from the comparison table into actionable insights using a two-column table.

**Table Columns:**
*   `Observation`: A factual statement derived from the data (e.g., "A beats B in every setting").
*   `Conclusion`: The takeaway or root cause, formatted in **bold** (e.g., "**Model quality matters a lot**").

--- (Horizontal Rule)

## 3. Strengths & Weaknesses Section
**Heading:** `## Strengths & Weaknesses`

This section provides a balanced, qualitative evaluation of each entity or configuration tested.

**Table Columns:**
*   `[Entity/Configuration]`: The specific subject being evaluated.
*   `Strength`: The primary advantage, best use case, or standout feature.
*   `Weakness`: The main drawback, limitation, or worst-case scenario.
